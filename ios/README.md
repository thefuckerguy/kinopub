# WooF.Play (iOS и iPadOS)

Нативный клиент для iPhone и iPad поверх API kino.watch и существующего `kinopub-gui`.

## Возможности версии 0.3.9

- вход в kino.watch по коду устройства;
- новинки, каталог, подборки, «Я смотрю», отдельные подписки, группы закладок и история;
- создание и удаление групп закладок, добавление и удаление в них фильмов и сериалов;
- автоматическая постраничная дозагрузка каталога, подборок и их содержимого;
- подписка и отписка от фильмов и сериалов из карточек и страницы фильма;
- загрузка постеров через совместимый с CDN кэшируемый клиент;
- полноэкранный онлайн‑ и офлайн‑просмотр без системных элементов управления плеером, с отдельной кнопкой открытия и выбором озвучки;
- локальное сохранение позиции при закрытии и синхронизация позиции с аккаунтом;
- фоновая загрузка HLS для офлайн‑просмотра на iPhone и iPad;
- восстановление доступа к загруженным HLS‑пакетам после обновления приложения;
- живой таймер срока локальной подписи в настройках приложения;
- безопасное удаление фильма, сериала целиком или отдельного эпизода из памяти устройства;
- локальный раздел «Буду смотреть» со значком глаза;
- локальный раздел «Персональный просмотр», содержимое которого не отправляется в KinoPub и не видно другим пользователям аккаунта;
- выбор качества, озвучки и хранилища перед загрузкой;
- адаптивный интерфейс для компактных экранов iPhone и больших экранов iPad;
- получение персонального зеркала во встроенном браузере и установка выданного HTTPS‑адреса одной кнопкой;
- безопасное управление пятью слотами устройств: браузеры не считаются слотами, показываются последнее появление и занятость, текущее и недавно активные устройства защищены от отвязки;
- профиль, изменяемое имя устройства и быстрые страницы аккаунта;
- карточная офлайн‑библиотека с поиском, фильтрами и сортировкой;
- внутренняя папка `Файлы → На моём iPhone/iPad → WooF.Play → Movies`;
- подключение папок и внешних USB‑дисков через security‑scoped bookmarks;
- чтение `.kinopub-state.json` от настольного приложения и восстановление файлов после переноса диска между компьютером и iPhone/iPad;
- группировка серий по сезонам в онлайн- и офлайн-карточках;
- загрузка сезона целиком или выбранных серий с общими параметрами качества, озвучки и хранилища;
- ручные отметки просмотра и автоматическая отметка после 90% видео;
- проверка новых серий и загрузка недостающих эпизодов;
- OAuth‑токены хранятся в Keychain.

## Сборка

1. Откройте `KinoPad.xcodeproj` в Xcode.
2. Выберите схему **KinoPad** и симулятор iPhone/iPad либо подключённое устройство.
3. Для физического устройства выберите свою Team в **Signing & Capabilities**.

Командная проверка:

```sh
xcodebuild -project KinoPad.xcodeproj \
  -scheme KinoPad \
  -destination 'platform=iOS Simulator,name=iPhone 17e' \
  test
```

## Установочный IPA

Development‑пакет для зарегистрированных в Xcode устройств собирается так:

```sh
./scripts/build-development-ipa.sh
```

Готовый файл появится в `build/installer/`. Его подпись действует только для устройств, добавленных в provisioning profile выбранной Team. Для установки на другие iPhone/iPad используйте TestFlight либо сначала подключите устройство к Xcode и пересоберите пакет. Подписанные IPA не следует публиковать в открытом репозитории: профиль может содержать идентификаторы зарегистрированных устройств.

Для установки на дополнительные устройства и обновления из ветки `main` используйте macOS‑приложение [`macos/WooFInstaller`](../macos/WooFInstaller). Оно проверяет IPA, запускает официальный процесс включения режима разработчика, безопасно регистрирует новое устройство через Xcode и умеет выполнить `git pull --ff-only`, собрать, подписать и установить свежую версию на все доступные по Wi‑Fi iPhone и iPad одной кнопкой.

Установка для других пользователей без кабеля и Developer Mode описана в [руководстве по TestFlight](TestFlight.md). Для неё требуется платная Apple Developer Program.

## Форматы

AVPlayer надёжно воспроизводит MP4, M4V, MOV, TS, HLS и загруженные HLS‑пакеты. MKV/AVI видны в библиотеке, но для гарантированного воспроизведения этих контейнеров нужен отдельный MobileVLCKit‑модуль.
