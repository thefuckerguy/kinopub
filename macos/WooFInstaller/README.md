# WooF Installer для macOS

Графическая утилита для безопасной установки WooF.Play на принадлежащие вам iPhone и iPad.

## Что умеет

- находит доверенные устройства, подключённые по USB или Wi‑Fi;
- показывает установленную версию WooF.Play;
- одной кнопкой проверяет обновления, собирает, подписывает, устанавливает или обновляет и запускает WooF.Play;
- позволяет выбрать и сохраняет способ подписи **AppleCert** или **Xcode** для локальных, автоматических, Git‑сборок и обновлений по Wi‑Fi;
- обновляет за один запуск все доступные по Wi‑Fi iPhone и iPad, продолжая работу при сбое одного из них;
- по явному нажатию устанавливает / обновляет и запускает официальный AltServer для подготовки фонового обновления подписи через AltStore Classic;
- одной кнопкой передаёт выбранный IPA прямо в контейнер AltStore Classic на выбранном доверенном устройстве и открывает импорт;
- проверяет подпись, bundle ID, срок профиля и наличие устройства в выбранном IPA;
- устанавливает и запускает готовый development/ad hoc IPA;
- регистрирует новый телефон через Xcode Automatic Signing, собирает и устанавливает приложение;
- запускает официальный процесс Apple для включения режима разработчика и объясняет подтверждение на устройстве;
- проверяет новые коммиты в `origin/main`, выполняет только безопасный `git pull --ff-only` и ставит свежую сборку;
- проверяет GitHub Releases, скачивает IPA по HTTPS и сверяет SHA‑256, когда GitHub предоставляет digest.

Утилита не обходит ограничения Apple. На Mac должен быть установлен Xcode, а на телефоне — включён режим разработчика. Выберите способ подписи в сегментированном селекторе **«Способ подписи»** в карточке установки. Выбор сохраняется между запусками. При первом запуске выбирается AppleCert, если он уже настроен; иначе выбирается Xcode. Сохранённый выбор всегда имеет приоритет. После сохранения AppleCert автоматически выбирается AppleCert, а после его удаления — Xcode.

В режиме **Xcode** сборка выполняется с Xcode Automatic Signing; в **Xcode → Settings → Accounts** должен быть добавлен ваш Apple ID. Для нового устройства используется официальный флаг Xcode `-allowProvisioningDeviceRegistration`. Сохранённый AppleCert при этом игнорируется. В режиме **AppleCert** сборка подписывается только сохранёнными сертификатом и профилем; Xcode Automatic Signing не используется, а при отсутствующих или неполных данных сборка останавливается без переключения на Xcode. Для каждого устройства перед подписью проверяется его UDID в профиле.

## AppleCert: подпись сохранённым сертификатом

В блоке **«Подпись AppleCert»** выберите `.p12`, соответствующий `.mobileprovision` и введите пароль от `.p12`. Нажмите **«Сохранить AppleCert»**. Установщик проверит пароль, совпадение сертификата с профилем, срок действия и bundle ID `app.xigua7648.gray5696`, затем выберет AppleCert в селекторе. Кнопки локальной сборки, автоматической установки / обновления, Git‑обновления и обновления по Wi‑Fi используют текущий выбор селектора. Чтобы использовать Xcode, переключите селектор на **Xcode**: в этом режиме сохранённые AppleCert данные не используются. Если AppleCert выбран, но его данные отсутствуют или повреждены, действия сборки отключены либо завершаются явной ошибкой; автоматического перехода на Xcode нет. Если устройства нет в профиле, добавьте его в Apple Developer и замените профиль в установщике.

Проверка учитывает `ApplicationIdentifierPrefix` и фактический prefix из entitlement `application-identifier`; он может отличаться от `TeamIdentifier`. Wildcard-профили `PREFIX.*` и `PREFIX.app.xigua7648.*` конкретизируются для `app.xigua7648.gray5696`, а explicit bundle ID допускается только при точном совпадении.

Пароль хранится только в macOS Keychain. Копии `.p12` и профиля лежат в `~/Library/Application Support/WooFInstaller/AppleCert` с правами `0700` для папки и `0600` для файлов. В режиме AppleCert при каждой подписи сертификат импортируется во временную связку ключей, доступ к закрытому ключу выдаётся `codesign`, а временная связка ключей удаляется после операции. Xcode собирает приложение без подписи; установщик встраивает профиль, подписывает вложенный код и основной пакет с разрешёнными entitlements (включая DER), проверяет подпись и сохраняет IPA в закрытой папке `~/Library/Application Support/WooFInstaller/SignedIPA`. В режиме Xcode приложение собирается и подписывается Xcode Automatic Signing. Путь к последнему IPA показывается в поле **«Подписанный IPA»**; его можно повторно проверить, установить или передать в AltStore. Подписанный AppleCert IPA может содержать UDID устройств из профиля, поэтому не публикуйте его без необходимости. Кнопка **«Удалить AppleCert»** удаляет сохранённые копии и пароль из Keychain и выбирает Xcode.

Если macOS не распознаёт формат `.p12` (например, возвращает ошибку декодирования), установщик может преобразовать его в совместимый PKCS#12. Для этого нужен Homebrew `openssl@3` по стандартному пути `/opt/homebrew/opt/openssl@3/bin/openssl` или `/usr/local/opt/openssl@3/bin/openssl`; системный `/usr/bin/openssl` создаёт совместимый контейнер. Исходный пароль и закрытый ключ передаются процессам только через каналы ввода, не через аргументы командной строки. На диске временно лежат только зашифрованные `.p12`, открытые сертификаты и новый случайный внутренний пароль в закрытой папке; временные файлы удаляются после преобразования. Сохранённый совместимый `.p12` защищён новым паролем, который хранится в Keychain. При ошибке проверки пароля преобразование не запускается — проверьте введённый пароль или повторно экспортируйте сертификат.

Профиль должен быть действительным и разрешать bundle ID приложения и целевое устройство. Если проект позже добавит extension с отдельным bundle ID, профиль должен разрешать и его; иначе установщик остановит подпись с объяснением. Фактическую подпись необходимо проверить на своём сертификате и устройстве: автоматические тесты используют только синтетические данные и не импортируют реальный ключ.

Если на iPhone установлен код‑пароль, Apple может отклонить автоматическую команду `devmodectl`. В этом случае не отключайте защиту: включите режим вручную в **Настройки → Конфиденциальность и безопасность → Режим разработчика**, подтвердите перезагрузку, после запуска нажмите **Включить** и введите код‑пароль.

При первой development‑установке iPhone может потребовать отдельно подтвердить сертификат в **Настройки → Основные → VPN и управление устройством**. Установщик распознаёт эту ситуацию и показывает точную инструкцию.

Для обновлений по воздуху каждое устройство нужно один раз сопрячь с Mac и доверить ему. Затем Mac и iPhone/iPad должны быть в одной локальной сети, а режим разработчика должен быть включён. Кнопка **«Обновить все по Wi‑Fi»** сама обновит список, получит актуальный `main` и последовательно установит свежую сборку на все доступные устройства. Офлайн‑устройства можно обновить следующим нажатием кнопки, когда они станут доступны по Wi‑Fi.

Чтобы сразу проверить текущие правки на выбранном iPad, нажмите **«Собрать локальные изменения и установить»**. Xcode соберёт текущую версию проекта, включая незакоммиченные правки добавленных в проект файлов; подпись и установка используют выбранный способ — AppleCert или Xcode. Новые файлы сначала нужно добавить в Xcode-проект. Эта команда не выполняет `git pull`, не переключает ветку и не изменяет исходники. Кнопки автоматического обновления и обновления всех устройств по Wi‑Fi требуют чистых отслеживаемых файлов до синхронизации и останавливаются с предупреждением при локальных правках; после этого используйте локальную сборку. Для добавления правок из GitHub сначала самостоятельно сохраните их, затем выполните Git-обновление при чистом рабочем дереве.

## AltServer и подпись на 7 дней

В блоке **«Обновление подписи через AltStore (7 дней)»** нажмите **«Установить / обновить AltServer»**. Установщик проверит имеющийся AltServer, запросит [официальный канал обновлений](https://altstore.io/altserver/sparkle-macos.xml), скачает выпуск только с HTTPS-адреса `cdn.altstore.io/file/altstore/altserver/…` и установит отдельное приложение в `/Applications/AltServer.app`. Более новая установленная версия не понижается. Перед обновлением работающий AltServer нужно завершить через его меню. **«Открыть AltServer»** проверяет и запускает установленное приложение без сетевой загрузки.

AltServer не включается в пакет WooF Installer и не переподписывается. Перед извлечением проверяются ZIP-пути, типы файлов, относительные ссылки фреймворков, соответствие заголовков/дескрипторов и CRC. Данные предварительно декодируются блоками в памяти для проверки реального размера: архив ограничен 128 МиБ, распакованные данные — 512 МиБ; скрытые записи и запись через ссылки запрещены. Перед копированием и запуском проверяются bundle ID `com.rileytestut.AltServer`, подпись Apple Developer ID с Team ID `6XVY5G3U44` и разрешение Gatekeeper. При ошибке проверки установка прекращается. При отсутствии прав на `/Applications` установщик объясняет ручную установку через Finder; пароли администратора он не запрашивает. При замене предыдущая официальная версия сохраняется в скрытом `/Applications/.AltServer-before-WooF-….app` для восстановления через Finder (`⌘⇧.` показывает скрытые файлы).

Для завершения настройки выполните [официальную инструкцию AltStore Classic](https://faq.altstore.io/altstore-classic/how-to-install-altstore-macos):

1. Подключите iPhone/iPad по USB и подтвердите доверие. В Finder включите **«Показывать этот iPhone/iPad при подключении к Wi‑Fi»**; на устройстве включите режим разработчика.
2. В значке AltServer в строке меню выберите **Install AltStore → устройство**. Apple Account, пароль и код 2FA вводите только в интерфейсе AltServer. WooF Installer не получает и не сохраняет учётные данные Apple.
3. Выберите устройство и IPA WooF.Play, затем нажмите **«Передать IPA в AltStore»**. Установщик обнаружит AltStore Classic на выбранном устройстве, скопирует IPA через доверенное USB/Wi‑Fi соединение и откроет импорт. Подтверждение установки и, если требуется, вход в Apple Account завершите внутри AltStore на устройстве. Сообщение об успешной передаче означает копирование и запуск AltStore, а не завершённую установку. Если iOS не даёт доступ к контейнеру, перенесите IPA через AirDrop / iCloud Drive и импортируйте кнопкой **«+» в My Apps**; **«Показать IPA в Finder»** помогает найти файл. Обычная установка через Xcode или WooF Installer сама по себе не делает приложение управляемым AltStore.
4. Разрешите фоновое обновление AltStore в iOS и включите **Background Refresh** в AltStore. Держите Mac включённым, AltServer запущенным, а устройства — в одной сети; при необходимости добавьте AltServer в объекты входа macOS. Проверьте **Refresh All** в AltStore до истечения подписи.

Для бесплатной учётной записи подпись действует 7 дней. AltStore [пытается обновлять её в фоне](https://faq.altstore.io/altstore-classic/your-altstore), но время фоновой задачи выбирает iOS, поэтому гарантировать продление нельзя. Это продление подписи текущей версии, а не получение свежей WooF.Play из GitHub: новый IPA нужно импортировать в AltStore отдельно. Завершение установки AltServer означает готовность Mac; установку AltStore, вход и первое обновление нужно завершить на устройствах вручную.

Передача не открывает HTTP‑сервер и не публикует IPA в локальной сети. Используются штатные `devicectl device info apps --include-container-paths`, `device copy to --domain-type appDataContainer` и `device process launch --terminate-existing --payload-url altstore-classic://install?url=…` для AltStore 2.2 и новее; для более старых версий используется `altstore://install?url=…`. В ссылке передаётся percent-encoded `file://` URL IPA из контейнера AltStore. Запуск с `--terminate-existing` передаёт ссылку как уже работающему, так и только что запущенному AltStore. [AltStore Classic принимает локальный IPA](https://github.com/altstoreio/AltStore/blob/576e1e88e8c9e771f71e0ccc3e4935365fc4a286/AltStore/AppDelegate.swift). Поддерживаются исходный bundle ID Classic и варианты с Team ID, созданные AltServer; PAL и похожие идентификаторы не принимаются. При нескольких копиях Classic выбор не угадывается. Требуются доступ к контейнеру, доверие к Mac и Developer Mode.

На Mac передаётся отдельная копия обычного файла до 512 МиБ в папке с правами `0700` (сам файл — `0600`); ссылки, специальные файлы, пустые и слишком большие IPA отклоняются. Именно эта копия проходит проверку IPA и bundle ID перед передачей; после успеха или ошибки она удаляется. Старый срок профиля и список UDID не ограничивают этот сценарий: AltStore переподписывает приложение. На устройстве используется единственный файл `tmp/WooFInstaller/WooF.Play.ipa` внутри контейнера AltStore: повторная передача заменяет только его, а iOS может очистить временную папку. Копирование ограничено 120 секундами, поиск и запуск — 30 секундами. Новый импорт выполняйте после завершения предыдущего в AltStore.

## Сборка

```sh
./scripts/build-app.sh
```

Готовое приложение появится в `build/WooF Installer.app`. Его можно перенести в `/Applications`.

Подписанные IPA не публикуются автоматически: development/ad hoc profile может раскрывать UDID разрешённых устройств. Локальная сборка, Git‑обновление и обновления по Wi‑Fi подписываются выбранным способом из **«Способ подписи»**. AppleCert не переключается на Xcode при ошибке; для Xcode Automatic Signing явно выберите режим **Xcode**.
